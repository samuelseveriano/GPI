# GPI v0.7.1 — API Stability & Advanced Market Intelligence

Versão de estabilização. Ordem seguida: auditoria das APIs → pipeline de coleta/persistência → sincronização →
visualização → ML → insights comerciais → dashboard → testes → executável Windows.

Legenda usada em todo o documento:

- **IMPLEMENTADO** — código presente na branch.
- **TESTADO** — coberto por teste automatizado (pytest e/ou smoke test do executável no Windows do CI).
- **VALIDADO COM DADOS REAIS** — executado contra a API real e com dados gravados no SQLite (job 2 do CI ou
  validação manual do proprietário). Nada é marcado como validado a partir de mocks.

## 1. Defeito do Mercado Livre ("0 requisições · 0 registros · Atualizado")

**Sintoma.** OAuth funcionando, `GET /trends/MLB` retornando 50 termos, mas a sincronização mostrava 0 requisições,
0 registros, 0,0 s, estado "Atualizado" e a mensagem "Dados considerados atualizados pela política de sincronização".

**Causa (comprovada por teste de regressão).**

1. A primeira tentativa falhou (antes da autorização); o job ficou em `failed` com backoff exponencial.
2. Na execução seguinte o planejador não encontrou jobs "devidos" e, sem jobs, o painel mostrava "em dia" —
   **mesmo sem nenhuma coleta bem-sucedida na história da fonte**.
3. O botão Sincronizar não ignorava o backoff local, então a fonte ficava bloqueada até o fim do backoff.
4. As fontes que gravam diretamente em `search_observations` (ml_trends, Google Trends, Ads…) não informavam o que
   gravaram; o resumo sempre exibia 0 registros.

**Correção (IMPLEMENTADO · TESTADO).**

| Item | Onde |
|---|---|
| "Atualizado / em dia" só com `last_success` registrado e fonte validada | `market/sync.py` |
| Novos estados: `sem_novidades`, `pendente` (mostra último erro e próxima tentativa), `sem_coleta` | `market/sync.py`, `frontend/v061.js` |
| Job `done` de fonte sem nenhum sucesso volta a ser devido | `SyncManager._is_due` |
| **Sincronizar / Atualizar fonte / Tentar novamente** = atualização manual controlada: ignora TTL e backoff **locais**, nunca cotas do provedor (429/Retry-After continuam respeitados) | `sync.start(..., manual=True)`, `/api/sync/start {fontes, manual}` |
| Contagem de novos/revisados também para gravações diretas | `sources5._observe_and_store` → `ctx.obs_counts` |
| `ml_trends` e `mercadolivre` compartilham a mesma resposta (cache 1 h) — sem requisição duplicada | `connectors/restricted.py`, `sources5.py` |
| OAuth HTTPS (GitHub Pages) **não foi alterado** | — |

Testes: `tests/test_v071_sync.py` — primeira coleta grava e conta os 50 termos; falha anterior aparece como
"pendente" e a atualização manual recupera; job concluído sem sucesso volta a ser executado; cache compartilhado;
persistência após reabrir o banco.

**VALIDADO COM DADOS REAIS:** pendente do proprietário (o CI não tem o token do Mercado Livre — ver
`TESTE_CORPORATIVO.md`, passos 4–6).

## 2. Auditoria de todas as fontes (matriz A–F)

`market/audit.py` descobre os conectores automaticamente no registro e calcula, a partir do estado **real** do banco:
A configuração · B autenticação · C coleta · D processamento · E persistência · F visualização, e a fase final
(Não configurada / Aguardando autorização / Autenticada / API validada / Coletando / Dados armazenados / Funcional /
Restrita / Falha / Sem coleta ainda). Um token salvo leva no máximo a "Autenticada"; "Funcional" exige coleta
bem-sucedida, registros gravados e registros ligados a produtos.

- Interface: **Saúde das Fontes** (tabela A–F, integridade do banco, botões Atualizar fonte / Diagnosticar).
- API: `GET /api/sources/audit`, `GET /api/db/integrity`.
- CI: o job 2 gera `auditoria_fontes.md`. O resultado real está em [`API_AUDIT.md`](API_AUDIT.md).

## 3. Banco de dados

- Backup automático (`data/backups/gpi_antes_migracao_v{a}_para_v{b}_*.sqlite`) antes de qualquer migração de um
  banco existente. O banco nunca é apagado.
- `Database.integrity()`: `PRAGMA integrity_check`, `foreign_key_check`, contagens por tabela, observações órfãs,
  modo de journal e versão do esquema; as contagens da interface vêm do próprio banco.

## 4. Machine learning (detalhes em [`ML_VALIDATION.md`](ML_VALIDATION.md))

- Backtesting por origem móvel **sem vazamento** (teste dedicado).
- Candidatos: Naive, Seasonal Naive, SES, Holt, Holt amortecido, ETS automático, Holt-Winters, SARIMA e modelos ML
  globais quando há histórico suficiente. A auditoria mostrou que o Naive vencia em tendência linear porque só havia
  Holt amortecido — Holt e ETS automático foram incluídos.
- Quando nenhum modelo supera o Naive, o próprio baseline é usado e a interface informa ("nenhum modelo superou o
  baseline").
- Intervalos 80/90/95 aninhados; intervalos conformais só para níveis defensáveis com o número de resíduos
  disponível (antes, com poucos resíduos, os três níveis saíam idênticos).
- Séries curtas: nenhuma previsão artificial (status `exploratoria`).
- Interesse de busca **não** é venda — aviso em todos os insights.

## 5. Inteligência de Oportunidades e Insights do GPI

- Nova página **Inteligência de Oportunidades**: crescendo, perdendo interesse, crescimento consistente, possíveis
  modismos, sazonais, EUA antes do Brasil (lead-lag exploratório), múltiplas fontes, merecem investigação
  (Opportunity Score ≥ 55 e cobertura de evidências ≥ 40), precisam de mais dados; clusters KMeans interpretáveis.
- Classes (critérios em `products/insights.py`): EMERGENTE, CRESCIMENTO CONSISTENTE, ACELERAÇÃO, ESTÁVEL, SAZONAL,
  POSSÍVEL SATURAÇÃO, DECLÍNIO, EVIDÊNCIA INSUFICIENTE.
- Painel **INSIGHTS DO GPI** em cada produto (situação, crescimento por janela, persistência, fontes com evidência,
  volatilidade, previsão, confiança, scores, prontidão regulatória, próxima ação, limitações).
- Opportunity Score, Evidence Coverage, Forecast Confidence e Import Readiness são exibidos separados; o score
  **não é probabilidade**; API ausente aparece como "sem dados", nunca como demanda baixa.
- Texto gerado por regras determinísticas a partir dos indicadores — nenhuma LLM inventa números.
- Dashboard: 6 painéis de destaque. Relatórios: seção "Insights do GPI".
