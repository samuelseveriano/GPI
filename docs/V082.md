# GPI v0.8.2 — eBay Production Integration & Meta OAuth Fix

Branch `fix/gpi-v0.8.2-ebay-meta-integrations`, criada a partir da `main` (que já contém v0.7.1, v0.8 e v0.8.1 —
PRs #13, #14 e #15 mesclados). Sem merge automático. Modelos de ML, banco e histórico intocados.

## Auditoria inicial

### Meta
| Item | Achado |
|---|---|
| Causa do "Retorno inválido ou incompleto" | `relay.js` aceitava códigos de no máximo **300** caracteres (backend: 1.024). Códigos do Login do Facebook passam de 300; o `state` do GPI passava. Reproduzido com o relay antigo (301, 412 e 2.048 caracteres recusados). |
| State | 256 bits, 10 min, uso único, ligado ao GPI — correto; faltava distinguir expirado × reutilizado × desconhecido. |
| Token | era gravado **antes** de ser conferido; agora só depois de `debug_token` confirmar validade e o mesmo App ID. |
| App ID | uma única fonte (credenciais com DPAPI); URL de autorização, troca e verificação usam o mesmo valor; troca de App ID descarta tokens do app anterior (v0.8.1). |
| Retorno pelo GitHub Pages | o código passa pela query de uma página pública (logs de CDN, histórico); mitigado por App Secret só no GPI, código de uso único e curta duração, `no-referrer`. Alternativa sem servidor público: modo localhost (app em desenvolvimento). Detalhes em [META_OAUTH_FIX.md](META_OAUTH_FIX.md). |

### eBay
| Item | Achado |
|---|---|
| Conector | Browse API `item_summary/search` (EBAY_US), token de aplicativo com `api_scope`. |
| Dados guardados | `market_listings`: item, título, preço, categoria, URL e **nome de usuário do vendedor**; respostas brutas no **cache HTTP** por 12 h; podem existir em **backups** SQLite. |
| Isenção | **não elegível**: a isenção é para apps que não guardam dados do eBay; o GPI guarda histórico de anúncios. |
| Protocolo oficial | GET: `SHA-256(challengeCode + verificationToken + endpoint)`, JSON. POST: `x-ebay-signature` = base64 de `{alg, kid, signature, digest}`; chave em `/commerce/notification/v1/public_key/{kid}` (cache de 1 h); ECDSA/SHA-1 sobre `JSON.stringify(mensagem)` — conforme o SDK oficial do eBay; respostas 200/201/202/204; reenvio até confirmação; endpoint marcado como fora do ar após 24 h; 30 dias para corrigir. |
| Browse API em produção | o eBay indica que Buy APIs em produção podem exigir aprovação; o diagnóstico separa "API não autorizada" de "permissão ausente". |
| Rede corporativa | o GPI fala com o Worker e o eBay por HTTPS de saída usando o mesmo cliente HTTP (proxy e certificados corporativos); nada é aberto para entrada no computador. |
| Infraestrutura gratuita | Worker + D1 + Cron no plano gratuito; nenhum recurso pago. |
